# 2026年10月14日 Linux 版内蔵カードリーダー対応の実装の記録

この文書は、Linux 版の内蔵カードリーダー対応 (`feature/linux-card-reader` ブランチ) を、どの外部の実装を土台にし、何を取り込み、何をどう直したかを記録したものです。  
現在の設計は [`pcsc/README.md`](../pcsc/README.md) に、実機で確かめた範囲は [実機確認の記録](20261014_linux_card_reader_validation.md) にあります。  
2026年7月24日時点の外部実装の評価は [`20260724_external_change_assessment.md`](20260724_external_change_assessment.md) にあり、この文書はその後の状況を踏まえた続きです。

## 土台にした実装

7月の評価の後に更新されたフォークと PR を、現在のコードで調べ直しました。

| 実装 | 状況 | 扱い |
|---|---|---|
| PR #43 (ouvill 氏) | PX-MLT5PE 系に対応。カーネルは機器の寿命・排他・共有電源だけを持ち、T=1 は Windows 版の `smart_card.cpp` をそのまま使う | 土台として取り込んだ |
| yyya-nico 氏のフォーク | 利用者を含めて約半年の実績があるが、T=1 を独自に実装していて、ACAS・APDU 全体の期限・受信フレームの誤り検査・抜去後の状態破棄・USB 切断後の扱いを満たしていない | 実戦で見つかった不具合 (2台目のリーダーの拒否、登録失敗後に class が残る件、64bit の配置先) を試験の観点として参照した |
| makeding 氏のフォーク | PX-Q3U4 と ACAS の通信の報告があり、PX4 系の2基連動の電源管理を Windows 版から移している | GPIO のキャッシュの不具合の修正を取り込み、電源管理は Windows 版から改めて移した |
| glyzinie 氏のフォーク | PX-M1UR で、本家の `smart_card.cpp` を改変せずに ATR から IFS まで通した | `smart_card.cpp` がそのまま Linux で動く外部の裏付けとして扱った |

PR #43 を土台にしたのは、7月に決めた構成 (カーネルは機器の寿命・排他・共有電源・UART 操作だけを持ち、T=1 はユーザー空間に置く) に沿っていた唯一の実装だったためです。

## PR #43 の取り込み方

PR #43 は、`develop` から作った自前のブランチへ、マージコミットとして取り込みました。  
他人の PR の先頭からブランチを作って延長すると PR の履歴と手直しが混ざるため、取り込みは自前のブランチへのマージで行い、手直しは後続のコミットに分けています。  
マージでは、次の変更を除きました。

- USB バス層 (`itedtv_bus`) にタスクごとの期限を持たせる変更と、それを試験する `driver/tests/`
- CI とリリースの workflow の変更と、deb を作るスクリプト

前者は、全機種の制御転送が通る共通部分にカードのためだけの状態を持たせる変更で、APDU 全体の期限は `smart_card.cpp` の検査で足りるためです。  
後者は、配布の方法を別に決めるためです。

## 手直しの内容

取り込んだ後に、次のように手直ししました。

- ioctl の構造体から期限を外し、`smart_card.cpp` を `develop` と同じ内容へ戻した
- ioctl を、全コマンドが共通の 264 バイトの構造体と ABI のバージョン番号を使う形から、Windows 版の `CardDevice` の関数と1対1のコマンドが必要な型だけを受け渡す形に作り直した。カーネルモジュールと IFD ハンドラーは利用者の環境で別々に更新されるので、公開した番号の意味は変えず、機能は新しい番号で追加する (古いモジュールは `ENOTTY` を返す) という Linux の ioctl で一般的なやり方で互換性を保ち、バージョン番号と予約フィールドは持たせていない
- Info.plist の配列を1行に1つずつ書くように直した。pcsc-lite は string 要素を行単位で読むため、1行に並べていた2つ目以降の機種 (PX-MLT5PE) が登録されていなかった
- ioctl の処理を機種共通層 (`px4_card.c`) へ移し、機種側は基板電源の参照を増減する関数だけを渡す形にした
- カードを閉じるときにリセット線 (GPIO H14) を Low へ落とす処理を削除した。Windows 版の `CloseCard()` にない操作で、理由も残されていなかったため
- コメントを、何のための処理かが読み取れる書き方に直した

## 対応機種の拡大

対応機種は、Windows 版の `HasCardReader()` に合わせて広げました。

- PX4 系: Q3 系は `dev_id` が 1 の側だけに登録し、2基連動の電源管理 (`px4_mldev`) に Windows 版の `MultiDevice::SetCardPower()` と同じカードの参照を加えた
- ISDB2056 系: チューナーを開くたびに電源を入れて閉じるたびに切る作りだったので、チューナーとカードのどちらが電源を使っているかの記録と、それを守るロックを追加した
- PX-M1UR: `m1ur_device.c` は `isdb2056_device.c` の写しで、違いは ISDB2056N 向けの分岐がないことと、チューナーを開く処理の途中で失敗したときの後始末 (2559c7b で ISDB2056 側だけ直していた) の有無だけだった。写しのままだと片方だけを直す不具合が残るため、Windows 版と同じく ISDB2056 の機種の1つとして統合した
- PX-S1UR・DTV03A-1TU: `s1ur_device.c` にも同じ後始末の漏れがあったので直したうえで、ISDB2056 と同じ形で対応した。その後、Windows 版と同じく PX-S1UR を `isdb2056_device.c` の1機種に統合し、設計の異なる ISDBT2071 (DTV03A-1TU) を `isdbt2071_device.c` に分けて、`s1ur_device.c` は削除した
- PXMLT 系: PX-MLT8PE の3チューナー側 (`PXMLT8PE3`) を除くすべてに登録した

## 取り込みを見送った外部の変更

カードリーダー以外のフォークの変更も調べ、次のように判断しました。

| 変更 | 判断 | 理由 |
|---|---|---|
| GPIO のキャッシュを書き込みの前に更新してしまう不具合の修正 (makeding 氏) | 取り込んだ | USB 転送が1回失敗すると、抜き差しするまで同じ GPIO の設定が読み飛ばされる。変わるのは失敗時の挙動だけ |
| ログファイルを毎回作り直す修正 (n0atl 氏) | 取り込んだ | 前回の末尾が残る問題を直す1行で、受信処理に関わらない |
| `O_NONBLOCK` と `poll` の対応 (kazuki0824 氏) | 見送った | 既存の利用者はブロッキングの `read()` を使っていて利点がなく、TS 受信の経路に未検証の変更が入る |
| ISDB-S の相対 TS 番号を 0〜7 に限る修正 (kazuki0824 氏) | 見送った | 差が出るのは実在しない番号を指定したときだけ |
| DKMS 3 系での deb の生成 (PR #42) | 見送った | メンテナが PR へのコメントで、生成方法を変えないと判断している |

## デバイスファイルとリーダー名

取り込んだ実装は `/dev/px4cardN` を作っていましたが、この N は登録順で決まり、USB の接続順で変わるため、Docker でコンテナへ渡すときや設定ファイルで固定するときに扱いにくいものでした。  
そこで、デバイスファイルは `/dev/px4card/<ID>` に作り、番号のファイルは作らない形にしました。  
登録は汎用の misc クラスから専用の `px4card` クラスに改め、sysfs では `/sys/class/px4card/<ID>` 、udev では `SUBSYSTEM=="px4card"` として、どこから見ても同じ ID で機器を指せるようにしました。  
misc クラスのままだとクラスの中に階層を作れず、sysfs の名前が登録順の番号 (`px4cardN`) か、`/` を `!` に置き換えた `px4card!<ID>` になるためです。  
`/dev/dvb` と同じく、最後の機器を外すとカーネルが `/dev/px4card` も消すため、コンテナでは Mirakurun の既定の構成と同じく `/dev` 全体をマウントする形を案内しています。  
ディレクトリを systemd-tmpfiles で残す方法も試しましたが、`/dev` 全体をマウントする既存の運用では不要なため採用しませんでした。

デバイスファイルの権限は、pcsc-lite 2.4 以降で pcscd が `pcscd` ユーザーで動くことに合わせ、libccid と同じく `pcscd` グループの `0660` にしました。  
チューナーと同じ `video` グループにすると、Ubuntu 26.04 (pcsc-lite 2.4.1) の pcscd がデバイスファイルを開けず、カードリーダーが一覧に出ないことを実機で確かめています。

ID には、Windows 版のリーダー名の `(ID: ...)` と同じ値を使い、Windows 版と Linux 版で同じ機器を同じ ID で識別できるようにしました。  
VID・PID・シリアル番号と Windows 版の INF の DeviceInterfaceGUIDs から小文字のデバイスインターフェースパスを組み立て、DriverHost_PX4 の `HashDevicePath()` と同じ 64bit FNV-1a で求めます。  
Windows 版で `PLEX PX-MLT5PE Smart Card Reader (ID: E0044EBBED627D79)` と表示される機器は、Linux 版では `/dev/px4card/E0044EBBED627D79` になります。

pcscd のリーダー名は、`PLEX PX-MLT5PE Smart Card Reader [ID: E0044EBBED627D79] (000042546005001) 00 00` の形です。  
pcscd は USB で検出したリーダーの名前を Info.plist の名前と USB の情報から組み立て、IFD ハンドラーには名前を返す手段がありません。  
そこで、pcscd が名前の材料として読む USB インターフェースの `interface` 属性を px4_drv が作り、`ID: <ID>` を返すことで、Windows 版の `(ID: ...)` と同じ ID をリーダー名に入れました。  
アプリケーションが呼ぶ PC/SC のライブラリ (libpcsclite) を置き換えれば Windows 版と同じ名前にもできますが、アプリケーションごとに差し込む必要があり、配布物と利用者の手間が大きく増えるため採用しませんでした。

PX-MLT5U は未発売の機種で、公式の Windows 用ドライバーに定義があるため対応していますが、Windows 版の INF がないので、パス末尾の `#{guid}` を省いて計算します。  
シリアル番号が使えない機器は `usb-<USB の接続位置>` を名前にし、名前が重複した場合は後から登録する側に `-1` 、`-2` を付けます。  
PID と GUID の表が Windows 版からずれると ID も変わるため、既存の IFD ハンドラーの `make check` に INF との照合を加えました。

## 配布

IFD ハンドラーは、`px4-drv-pcsc` という名前の amd64 と arm64 の deb として配布します。  
ソースは、利用者が探すときの語に合わせてリポジトリ直下の `pcsc/` に置き、pcsc-lite の慣習に従うバンドル名 (`ifd-px4.bundle`) と共有ライブラリ名 (`libifd-px4.so`) はそのまま使っています。

libstdc++ と libgcc を静的にリンクして依存を glibc だけにし、Ubuntu 20.04 のコンテナでビルドして、Ubuntu 20.04 以降と Debian 系のディストリビューションで動くようにしています。  
`.so` と `Info.plist` が1つずつのパッケージなので、debian/ ディレクトリと debhelper は使わずに dpkg-deb で作り、Depends は参照している glibc のシンボルの版から求めています。  
内蔵カードリーダーを使わない利用者は導入しなくてよく、既存の DKMS の deb の生成方法は変えていません。

## 残る課題

- 手元に実機がない機種での確認 (PX4 系の Q3 系と PE 版、PXMLT 系の PX-MLT5PE とそのリブランド品の DTV02A-5TS-P 以外、ISDB2056N 、PX-S1UR 、DTV03A-1TU)
- PX-M1UR 以外の機種での通信中のカードの抜去と再挿入、ACAS チップ、長時間の録画、ネイティブ Linux での TS の品質
- 同じ VID・PID・GUID・シリアル番号を持つ機器を複数台つなぐ場合の識別。ID は同じになり、Linux 版のデバイスファイル名に付く `-1` などの番号は接続順で決まる。DTV02A-1T1S-U と PX-M1UR はシリアル番号が同じでも、PID と GUID が異なるため ID は別になる
